# MicroClaw 内置 OpenClaw 2026.10.10 升级实施计划

日期：2026-11-07。源版本：OpenClaw 2026.10.5。目标：2026.10.10。

2026-11-09 策略调整：新的升级前恢复点改为白名单轻量备份，不再全量归档状态目录。
白名单、SQLite 一致性和恢复格式详见 `2026-11-09-lightweight-upgrade-backup.md`。
后续取消升级流程中的自动 Doctor，仅校验目标版本与 Gateway 停止状态，避免旧微信白名单迁移拒绝阻断安装；下文 Doctor 步骤属于原计划，以此调整为准。
桌面管理的 Gateway 禁用编译缓存并清理继承的缓存重派生标记，避免 10.10 另起子进程导致固定 PID 校验失败；节点身份、端口归属和配对校验保持不变。
文件保留与发布门槛不变；历史安装包和回归记录不能代替上述调整后重新打包的 EXE 验收。

## 目标与边界

交付面向已有用户的 MicroClaw Windows EXE 覆盖升级，而非仅升级开发机的 npm 包。
保留用户配置、凭据、会话、工作区、附件、插件账号、本地模型缓存与权限策略。
最终验收必须使用真实的 10.5 MicroClaw 安装结果，再运行新版安装流程；单元测试、修改版本字符串或新装成功不能代替迁移验收。
不使用本机真实用户数据，不发布到线上，不修改其他并行开发工作的功能。

## 执行顺序

### 1. 固定基线与获取发行包

- 保存当前 `dist/MicroClawSetup.exe`、安装清单和 SHA-256，确认其目标为 10.5。
- 获取官方 10.10 npm 元数据、完整包与 integrity；核对 Node engines 和关联插件实际版本。
- 对比实际发行包的 MXC 审批、cron/hooks/canvas、本地模型兼容变换点，保留未知版本拒绝和源码哈希验证。
- 网络失败或镜像缺包必须记录为阻断，不伪造哈希、不以源码标签冒充 npm 发行包。

### 2. 统一版本与打包资源

- 统一安装器目标、构建默认值/参数、CI、微信宿主 SDK 声明和测试夹具。
- EXE 与 MSIX 共用明确的核心资源准备和校验入口；禁止旧 ASAR 混入新版安装器。
- 在生成安装清单和打包之前核对 Node、ASAR 内包版本与安装目标；不一致直接失败。
- 产品版本独立于核心版本递增，避免更新检查仍识别为同一 MicroClaw 版本。

### 3. 适配运行时与数据升级

- 以 10.10 真实包审查 MXC 兼容补丁和本地模型 provider，不放宽安全校验来绕过不兼容。
- 微信继续验证 SDK exports、构建来源与文件树完整性，不覆盖登录态和既有启停策略。
- 沿用停止进程、校验备份、固定版本安装、Doctor、事务恢复流程；先备份再执行不可逆数据库迁移。
- 安装后校验实际被桌面解析并启动的核心，而非只看全局 npm 版本或 HTTP 200。
- Doctor 失败保留备份和事务，重试不重复升级包；不自动将新数据库交给旧核心。

### 4. 自动回归

- 版本入口一致性和陈旧资源拒绝。
- 10.5 → 10.10 受控升级的顺序、备份、失败后重试、同版修复和拒绝降级。
- MXC、微信、本地模型及 Gateway 启动兼容性；明确区分通过、失败和因缺少真实包而跳过。

### 5. 真实 EXE 覆盖迁移验收

在仓库 `build/` 下创建独立测试用户目录、安装目录、npm prefix、临时目录和端口；
隔离所有涉及用户路径的环境变量，禁止读写真实 `%USERPROFILE%/.openclaw`。

1. 运行保存的 10.5 安装产物，得到已安装的 MicroClaw 和真实 10.5 核心。
2. 由 10.5 创建可用状态：配置、代理、会话/消息、工作区和附件、插件策略；记录文件哈希、数据库逻辑快照和运行版本。
3. 停止测试进程，运行新版 EXE 的同一路径覆盖安装，不以手动复制新版文件替代安装。
4. 确认备份存在且校验成功、Doctor 完成、迁移事务提交。
5. 启动升级后的桌面/Gateway，验证真实核心为 10.10；检查历史消息、配置、工作区、附件和策略仍可访问，能新建会话并写入。
6. 重启并再次运行同版安装，确认幂等；在隔离测试环境注入 Doctor 失败，确认可恢复且不丢备份。
7. 核对只影响隔离目录，记录安装包 SHA-256、实际版本、命令、退出码和日志位置。

## 发布门槛

以下全部满足后，才可称为“升级完成，可向用户发布”：

- 安装器清单、内置 ASAR、安装后 npm 包、实际 Gateway 均为 2026.10.10。
- 必要的安全兼容层、微信和本地模型测试通过，无被掩盖的跳过。
- 真实 10.5 已安装环境覆盖升级通过；历史数据完整并能继续读写。
- 安装失败可恢复，同版安装幂等，无静默降级；备份定位明确。
- 新 EXE 生成并验签，产品版本递增；线上更新清单与下载链接另行审核发布。

### 安装验收的隔离范围

目录隔离不能隔离 Windows 的真实 HKCU、Defender 和系统快捷方式。
因此自动迁移验收从 EXE 中读取并执行真实冻结安装器的数据/桌面步骤，使用真实 npm、备份、Doctor、桌面解包和实际内置 Gateway；
仅将进程清单限定到测试目录，不停止其他实例，不执行 PATH/注册表、Defender、快捷方式和图形 UI 步骤。
完整用户点击式 EXE 安装仍须在独立 Windows VM/测试账号验收，不能把本机目录隔离测试称为完整系统安装验收。

可复用入口：`scripts/verify_exe_upgrade_stage.py` 与 `desktop/src/exe-upgrade-migration.integration.test.ts`。
