# 设置能力补齐：并行任务交付包

日期：2026-11-03。状态：规划，尚未派发、实施或完成动态验收。

## 1. 建议拆成多少个任务

**建议 20 个：16 个主线任务 + 4 个二期/条件任务；实际同时运行建议先控制在 4–6 个 Agent。**

不是把每个开关拆成一个任务，也不是按前端、后端横切。每个领域任务负责自己的界面、服务/IPC、错误处理、测试和交付说明，具备独立验收边界。只有设置入口与安全配置基础设施集中交付，避免多人反复修改同几个大文件。

20 个不是必须全部实现的承诺。已有能力只做回归；安全受限项先解释状态；开放新执行能力必须经过产品/安全决策。主线先补可用性和可观测性，不以关掉 MXC 换取功能数量。

## 4. 推荐派发顺序

### 第 0 批：先打通协作边界

- 并行派发 SET-01、SET-02；SET-05 可同时做路径审计和合成样本，不等 UI 外壳。
- SET-01 交付 `UI-M1`：分组/入口约定、最小面板挂载方式、兼容跳转、文案接入方式及测试。
- SET-02 交付 `CFG-M1`：只读快照、域操作、冲突/错误和状态 DTO 契约；以现有模型路径做回归，不要求先支持所有领域写操作。
- 两个里程碑冻结并完成最小可编译接入后，才让多个功能 Agent 同时开发正式接线。

### 第 1 批：基础可见性与独立领域

SET-03、SET-04、SET-05 的界面收尾、SET-11、SET-14 可并行。SET-03 提供统一状态结构后再进入下一批，避免每个功能发明自己的“已启用”。

### 第 2 批：业务领域闭环

SET-06、SET-07、SET-08、SET-09、SET-10、SET-12、SET-13、SET-15、SET-16 的写入范围相互隔离，可按 4–6 个槽位滚动派发。不要同时让所有 Agent 跑整仓构建或打安装包。

### 第 3 批：二期与安全门控

- SET-20 的只读检视可独立排期；没有开放原始配置写入的隐含承诺。
- D3 确认后做 SET-17；SET-18 再复用凭据引用和准入流程。
- D2、D4 确认且上游能力经过动态验证后，才派发 SET-19 的可执行阶段。
- 未决条件任务可先交付设计和能力探测，但不能把“设计完成/按钮存在”标为“执行能力已交付”。

## 5. 哪些地方不能让 Agent 同时改

| 共享热点 | 唯一接线负责人 | 领域 Agent 的提交方式 |
| --- | --- | --- |
| `SettingsView.vue`、`router.ts`、`App.vue`、`SidePanel.vue`、设置注册表、根级 i18n 资源 | SET-01 负责人/后续接线协调者 | 独立面板、feature 导出、隔离文案、最小接线请求 |
| `main.ts`、`preload.ts`、`renderer/env.d.ts`、`browser-openclaw.ts`、公共配置 DTO/策略接点 | SET-02 负责人/后续接线协调者 | 域服务、校验器、IPC registrar/客户端切片和测试；请求集中注册 |
| MXC 策略、命令同意、目录事务、执行授权、升级证明协议 | 原安全域维护者，经 SET-02 汇总审查 | 原则上只读；必要改动单独列出安全影响，不能由功能 Agent 顺手放宽 |
| 功能面板/域服务/域测试 | 对应任务 Agent | 在任务独占目录内完成前后端闭环，不改其他任务目录 |

设置大文件不做“一次性重写”。SET-01 先留兼容壳；领域迁移时逐个替换对应区块。共享文件接线必须随功能一同验收，不能成为“以后由别人接上”的遗漏。

## 7. 本轮明确不追齐

远程 Gateway 接管/远程节点配对、任意网络公开面、更多渠道/多账号全家桶、Gmail、浏览器自动化、记忆索引与导入、语音/摄像头/位置、主题导入、任意 OAuth 供应商、强制预算停机、全域原始配置编辑，均不是这 16 个主线的验收义务。其状态/理由应可发现，执行能力不凭 UI 开关承诺。

完整归属及“保留/审计/只读/条件/暂缓”的区别见 [85 项能力归属表](./coverage.md)。

## 8. 每个任务统一交付格式

1. **入口与范围**：正式版从哪里进入、全局/Agent/会话/应用偏好的作用域，哪些仅只读。
2. **变更文件**：独占目录和经协调者落地的共享接线；不夹带无关重构，不自行提交/推送/开 PR，除非另有授权。
3. **行为与安全**：保存→验证→生效/失败/恢复；requested/effective；不支持和未验证分别呈现。
4. **验证证据**：针对性测试命令/结果、合成配置与异常路径、正式构建入口验收截图；未运行的项明确列出，不伪称通过。
5. **残留与门控**：产品未决项、Runtime 不支持项、旧数据兼容风险，不通过扩大白名单来“解决”。

派发者为每个任务提供隔离工作区和已冻结的契约版本。Agent 只执行指定任务；发现额外缺口返回协调者，不侵入其他写入范围。合并前由协调者串行执行整体验收；主线完成不依赖所有条件任务开放。
