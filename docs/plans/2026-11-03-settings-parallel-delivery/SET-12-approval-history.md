# SET-12 已决审批历史、来源与持久授权关联

阶段：主线 P1；复杂度：L。依赖：SET-01、SET-02、SET-03。

## 目标与边界

让用户追溯“什么请求被谁/何种模式批准或拒绝”，而不是把持久授权列表当全部历史。主责 F07–F10，其中实时审批、精确授权/目录事务只保留和关联，新增是 F09。

## 实施范围

1. 复核现有 PermissionDialog、命令同意、Windows Node/MXC 审批生命周期和微信远程审批，定义可信的已决事件来源。
2. 最小事件包含稳定请求/关联 ID、时间、Agent/会话来源、执行模式、请求种类、决策、原因及一次/持久作用域；记录实际已生效决定，不根据 UI 点击猜测。
3. 建立受限、可轮转的本地记录和查询；上线前无历史时明确起始时间，不从当前授权推断过去所有批准。
4. 正式历史页支持时间/来源/类型/决定筛选、详情和已存在的精确授权关联；撤销仍调用原有受控链路，不在新页复制授权引擎。
5. 请求内容/参数可能含秘密和个人路径，记录前最小化/脱敏，说明保留/清理范围；允许始终执行模式下也区分免询问执行与人工批准。

## 写入范围

- 独占新增：`desktop/src/settings/approval-history/`、`desktop/renderer/src/components/settings/approval-history/` 及测试/合成事件。
- 审批/命令同意/远程审批实现只读；需要权威事件 hook 时向 SET-02 提交最小接点，由安全维护者审查。
- `PermissionDialog.vue` 原有决策行为不改；设置入口交 SET-01，IPC/类型交 SET-02。
- 诊断日志归 SET-04，聊天隐私归 SET-05；不能把审批原始参数批量塞进普通日志来代替审计。

## 验收

- [ ] 拒绝/一次允许/符合条件的持久允许、超时拒绝、远程决定、免询问模式有明确来源和语义。
- [ ] 重复/乱序事件不会生成矛盾记录；请求取消、连接断开和处理失败不伪造授权成功。
- [ ] 命令同意与 MXC 强度独立；host 模式不显示容器保护，审批不等于给全局目录放权。
- [ ] 从历史关联到现有精确授权并撤销后，原执行约束和恢复流程无回归。
- [ ] 记录不含合成秘密原值；大小/保留/清理、文件损坏/占用和“尚未采集历史”有用例。
- [ ] 新历史 IPC 只查询，不接受 renderer 直接追加“已批准”事件或改决策。

非目标：重写审批、修改 60 秒等现有交互策略、将精确命令改成宽泛白名单、同步到云端、补造旧历史。事件可信性与隐私是本任务的一部分，不能只交付表格 UI。
