# SET-19 Cron 写操作与 Hooks 的受控执行

阶段：条件 P2；复杂度：L。依赖：SET-02、SET-03、SET-16。产品/安全门控：D2、D4。

## 目标与边界

在已批准的执行模型下完成自动化变更与运行闭环，不把只读任务页直接加几个写 RPC。主责 E08–E10；Gmail 和任意外部事件源不在本任务内。

## D2 / D4 必须先确定

- 允许哪些任务类型、执行身份、模型/工具与目录权限；后台任务无人在场时如何审批/拒绝。
- 调度/时区、重试、取消、通知、运行记录和错过任务处理；保护期错过任务不能自动补跑。
- Hooks/Webhook 的认证、重放/幂等、速率/载荷限制与网络公开面；若没有安全监听方案，Hooks 阶段不开放。

未决时仅交设计/模拟，不解除 `windows-node-mxc-cron.ts` 的方法限制或恢复 fence。未通过安全准入的模式维持暂停。

## 实施范围

1. 先为批准的 Cron 子集完成创建/编辑/删除、计划预览、确认、冲突和生效验证；不允许任意任务载荷直通。
2. 手动运行与保存分开授权，提供目标/运行身份预览、运行 ID、取消/失败/重试语义和可查询历史。
3. 运行记录/告警只基于已验证事件，不靠 UI 倒计时伪造执行；任务内容和凭据不进入普通日志。
4. Hooks/Webhook 作为同一触发执行域的后续阶段，仅在网络与安全门控通过后开放已批准映射/重试；未做部分必须独立列出。
5. 模式切换、应用退出、重启和 generation 变化保持暂停/恢复边界，不自动重放遗漏事件或绕开工具审批。

## 写入范围

- 独占新增：`desktop/src/settings/automation-execution/`、`desktop/renderer/src/components/settings/automation-execution/` 及测试。
- SET-16 只读组件/store 在前序完成后按具体文件显式交接，不能同时修改。
- Cron fence、Hooks 入站、工具执行、网络公开面与授权接点的修改通过 SET-02 和安全维护者审查；main/preload 注册仍集中处理。

## 验收

- [ ] 非批准类型/作用域/来源/运行身份被拒绝，payload/路径/模板注入不能扩大执行能力。
- [ ] 冲突、重复提交、断连、超时结果未知和删除运行中任务有确定行为。
- [ ] 保护模式/过渡状态下禁止执行，切换后不会补跑保护期错过任务或重放事件。
- [ ] 调度跨时区/边界、取消、重试/幂等、运行失败和告警去重有合成测试。
- [ ] Hooks 若开放，认证/重放/速率/大小测试必须有证据；未开放不计作已交付。
- [ ] 正式入口展示 requested/effective 和实际执行历史，不以写配置成功替代运行验证。

非目标：云调度平台、Gmail、全事件源市场、无限后台自动批准、任意 Webhook 脚本。Cron 与 Hooks 的完成状态分别报告，不用“自动化已支持”掩盖未通过阶段。
