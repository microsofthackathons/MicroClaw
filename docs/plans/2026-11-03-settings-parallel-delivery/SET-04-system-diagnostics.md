# SET-04 实际版本、启动诊断、日志与诊断包

阶段：主线 P0/P1；复杂度：L。依赖：SET-01、SET-02。

## 目标与边界

让新机器启动失败时不用手工拼日志，也不把固定文案当成真实版本。主责 G01、G04、G05、G06、G07、G08、G14；节点/更新/采集配置只做到状态与说明，不开放远程配对或新更新机制。

## 实施范围

1. 展示真实应用、构建身份、固定/实际 OpenClaw、Node、Windows Node/原生 host、已知插件版本；读取失败显示未知并记录来源。
2. 汇总安装/桌面启动/Gateway 的阶段、耗时、失败和 transaction/generation 关联；Gateway 启不来仍可看本地诊断。
3. 复用 `startup-timing.ts`、`electron-lifecycle-diagnostics.ts`、`gateway-log-export.ts` 等已有能力，补受控文件日志来源、时间窗、级别筛选与有界读取。
4. 导出脱敏诊断包：来源 manifest、时间窗、组件身份、阶段和有限日志；默认不含聊天正文/附件/配置原文，选择后可预览范围。
5. 更新区域区分“桌面整包更新/受管安装”和 Runtime 身份；遵守现有整包升级/恢复/证明流程，不调用上游 `update.run`。
6. 明确日志/遥测当前采集来源、去向及已知保留边界；不借诊断任务擅自新增外传遥测或持久采集开关。

## 写入范围

- 独占新增：`desktop/src/settings/system/`、`desktop/renderer/src/components/settings/system/` 及测试。
- 如需扩展，独占既有 `startup-timing.ts`、`electron-lifecycle-diagnostics.ts`、`gateway-log-export.ts` 的本任务相关实现/测试；不改变启动协议或超时策略。
- 安装器和更新事务协议只读；读取导出路径由主进程限定，不能接受任意文件路径。
- 插件详细清单由 SET-15 提供；未知时版本卡显示来源/失败，不等待插件执行能力上线。
- 共享接线交 SET-01/02；内容隐私事实由 SET-05 审核，脱敏实现仍归本任务。

## 验收

- [ ] 模拟 Runtime 入口缺失、hash 不一致、未产生 ready、日志不存在/被占用，均可定位阶段且不误报成功。
- [ ] Gateway 离线时本地诊断仍可工作；日志轮转、超大文件、重复事件和时区边界有测试。
- [ ] 对 token、API Key、Authorization、URL query、用户路径和合成正文测试，导出无秘密原值；不能只依赖 renderer 脱敏。
- [ ] 路径穿越/非允许文件、导出取消、目标写入失败安全处理；读取有大小/行数/时间界限。
- [ ] 原重启功能和整包更新入口无回归；关于页不再用翻译常量伪装实际版本。
- [ ] 正式构建在干净测试机完成一次“启动失败→查看→导出”的验收，或明确列为待实机验证。

非目标：修复所有安装/启动故障、修改固定 Runtime/打包缓存、任意文件浏览器、远程设备后台、新遥测系统。必须区分“提供排障证据”和“已修复故障”。
