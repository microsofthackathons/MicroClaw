# 并行交付协作契约

本文件是待实现的边界约定，不是声称仓库已有通用设置平台。与任务文档冲突时，先缩小写入范围并找协调者，不能擅自接管共享文件。

## 1. 两个基础里程碑

### UI-M1：SET-01

- 最小设置 feature 接入约定：稳定 section ID、所属组、关键词/标题、组件入口、可见/只读状态；不建设通用插件框架。
- 建议新组件根为 `desktop/renderer/src/components/settings/<domain>/`；每个任务独占一个 domain，导出自己的面板与文案。
- 设置外壳仅负责导航、搜索、挂载和离开草稿的公共提示；业务保存状态属于领域面板。
- 旧 `/settings/:section?`、`/skills`、`/phone` 等保留有效跳转。搜索命中受限项仍显示原因，不能用隐藏入口绕过策略。
- 根级 i18n 合并方式在此冻结；功能文案放域内文件，由唯一负责人注册，避免二十个 Agent 同改 `zh-CN.ts`。

### CFG-M1：SET-02

- 交付可编译的读取/域提交最小示例、公共 DTO/错误契约、主进程/预加载接入方式及回归测试。
- 新服务建议根为 `desktop/src/settings/<domain>/`；主进程继续使用类似 `registerLocalModelHandlers` 的显式 registrar 与依赖注入，不开放任意 Gateway RPC 转发器。
- 公共类型的物理位置由 SET-02 确定，必须同时通过主进程与 renderer 的 TypeScript 构建；不得为了共享类型搬迁打包入口或引入循环依赖。
- 基础里程碑只承诺契约和已接入域；每个领域自行实现、测试自己的 adapter，不能假设通用写入已变得安全。

## 2. 公共语义：草稿、配置、策略和运行态

以下是最低语义要求，字段名在 CFG-M1 冻结；不要直接复制为未经验证的 API。

| 对象 | 最低内容 | 禁止的简化 |
| --- | --- | --- |
| 作用域 | application / global / agent / session；后两者带稳定目标 ID | 用当前路由值替代提交开始时的目标 |
| 读取快照 | 来源、读取时间、修订/hash、Gateway generation、受支持能力、脱敏配置 | 把离线或权限不足返回为空配置 |
| 域草稿 | 基于哪个修订、明确的字段操作、旧值/拟变更值、是否需要重启 | renderer 回写整份含未知字段/密钥的配置 |
| 能力状态 | requested、effective、可用性、原因码、来源与观测时间 | 单一 enabled 表示“想开启/策略允许/正在运行” |
| 提交结果 | operation ID、目标、保存/应用阶段、最新修订、恢复状态、安全错误 | 文件已写入就宣称运行态已生效 |

模式与权限至少分清：命令同意 `ask-when-needed/allow-always`、MXC requested/effective 强度 `off/full/limited-dacl`、host/容器运行位置、节点/Gateway generation。**host 模式不等于获得 MXC 保护；允许始终执行不等于新增目录权限；关闭 MXC 不等于自动批准所有命令。**

## 3. 受控保存

1. 主进程验证消息来源、payload 类型、大小、字段白名单、稳定目标、权限和当前 generation；不信任 renderer 带来的路径/能力结论。
2. 用最新快照验证预期修订，拒绝静默覆盖。涉及同一底层配置的不同领域也要协调，不是仅给各面板加局部锁。
3. 域 adapter 只应用授权字段，保留未知/高级字段；拒绝未批准变更。不得扩大 `config:write` 白名单或绕开其 MXC 禁止分支。
4. 优先复用 `model-config-application.ts` 已有的验证、`baseHash`、generation 和运行态确认语义；模型、目录策略、凭据、受管文件有不同事务，不能强行统成“写 JSON”。
5. 不支持安全写入的域维持只读/明确错误，不偷偷写文件、不临时关闭保护、不发送上游未广告的 RPC。
6. 重启/重新证明前预告影响；失败区分未写入、已保存未生效、部分完成、恢复成功/失败。恢复前再检查版本，不能覆盖其他客户端后续修改。
7. 幂等/重复点击、超时结果不确定、应用退出、切换 Agent、配置外部变化均有确定处理。无法证明生效时保留“待确认”，不伪造成功。

错误至少区分：validation、conflict、policy-blocked、unsupported、disconnected、stale-generation、apply-failed、recovery-failed。现有安全事务维持原 fail-closed 行为。

## 4. 共享文件接线规则

- SET-01 独占 UI 热点；SET-02 独占主进程/预加载/类型及公共安全接点。其他任务只读这些文件。
- 功能 Agent 提供自己的模块、测试和“接线请求”：导入/注册符号、IPC 名称、输入/输出、所需依赖、section ID、文案 namespace、旧区块替换点、要更新的 browser mock。
- 协调者应用最小接线改动并回传版本；功能 Agent 基于该版本完成端到端验收。接线落地前任务不得标为完成。
- UI-M1 / CFG-M1 达成后，对应负责人可关闭基础任务；继续担任唯一接线角色，不构成任务依赖环。后续接线工作计入发起该请求的功能任务交付。
- 不要求把整个 `main.ts` 或 `SettingsView.vue` 先拆完，也不批准每个 Agent 为方便而移动旧模块。
- 专有目录以外的旧文件改动，任务内逐一声明；未明确授权的共享文件先列请求。各领域旧测试随拥有的旧组件一起归属，不全压给基础任务。

## 5. 凭据、日志、审计和隐私

- UI 查询只返回是否已配置、引用 ID、来源/状态及遮罩 metadata；只读面板不能把配置中已有秘密原文发给 renderer。
- 输入新秘密的受控写接口，与读取/导出分离；禁止在异常、日志、测试快照、IPC debug、CSV 或诊断包中回显原值。
- SET-04 负责日志/诊断包脱敏，SET-05 负责聊天隐私覆盖事实，SET-12 负责审批事件审计；三者不是一个“全局 DLP”任务。
- 脱敏不能仅依靠 UI 开关：主进程导出前执行检查，用合成 Key/token/Header/路径及用户内容样本验证；默认不包含聊天正文和附件。
- 事件历史不存在时从上线起记录，明确“历史未采集”，不把旧的持久授权列表伪造成全量已决审批。

## 6. 统一验收维度

| 维度 | 最低用例 |
| --- | --- |
| 入口 | 正式打包配置可达；旧链接兼容；键盘/焦点/空态/错误态；中英文不出现裸 key |
| 数据 | 无配置、有旧配置、有未知字段；受保护凭据；缺失/非法字段；只读不发起变更 |
| 并发 | 同域和跨域修改冲突；外部客户端变更；切换目标；旧请求后返回；generation 变化 |
| 权限 | 当前实际支持的平台/模式；命令同意与沙箱独立；保护切换中拒绝不安全提交 |
| 运行 | 断连、超时、取消、重启、验证失败；保存但未生效明确；恢复失败不扩大权限 |
| 数据安全 | 审计/用量/日志导出含合成敏感样本；没有秘密、公式注入或非授权路径读取 |

单测从领域开始，整仓构建/回归由协调者串行做。主进程已有 Vitest，renderer 已有 Vitest / Vue Test Utils；优先沿用，不引入第二套框架。常用命令从仓库根执行：

```powershell
Push-Location desktop
try { npx vitest run <主进程相对测试路径> } finally { Pop-Location }
npm --prefix desktop/renderer run test -- <renderer 相对测试路径>
npm --prefix desktop run build
```

具体测试路径由领域 Agent 提供；根据当前命令执行策略获得必要确认。无须每个任务都打 EXE；最终发布前统一用正式构建和干净测试机验收，不能以 dev 面板截图替代。

## 7. 发给 Agent 的通用前缀
