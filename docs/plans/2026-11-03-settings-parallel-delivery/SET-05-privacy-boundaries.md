# SET-05 隐私覆盖审计、合成测试与准确承诺

阶段：主线 P0；复杂度：M。依赖：SET-01；链路审计、用例和结论可立即先行。

## 目标与边界

把“严格模式自动脱敏”和“敏感文件保护”的承诺与真实执行路径对齐。主责 F13、F14。交付是覆盖审计、回归用例、正确说明及已承诺路径内的局部修复，不是默认实现全渠道 DLP。

## 实施范围

1. 追踪桌面文本发送、附件内容/文件名、工具结果、微信入出站、后台任务等边界；逐项记录保护位置、是否启用、绕过条件和证据。
2. 复核 `stores/chat.ts`、`utils/pii-scanner.ts`、`utils/privacy-settings.ts`；仅已验证的路径才标为“受保护”。
3. 对 UI 静态敏感文件模式追踪真实读取/执行路径；不能用“列表存在”推断独立规则引擎存在。
4. 建立合成样本矩阵：五类 PII、密钥样式、假敏感文件、附件/工具结果等；未覆盖路径以测试/审计明确记录，不能把期待未覆盖写成应通过的断言。
5. 修正设置说明：basic/strict 实际范围、不覆盖项、历史删除影响；必要局部 bug 修复不扩大默认阻断范围。
6. 若产品选择 D5 的全渠道 DLP，另提架构/威胁模型和分期，不悄悄把本任务扩成出站代理项目。

## 写入范围

- 独占新增：`desktop/renderer/src/components/settings/privacy/`、隐私覆盖说明/合成 fixtures 及域测试。
- 既有域独占：`utils/pii-scanner.ts`、`utils/privacy-settings.ts`、`stores/chat.ts` 中已承诺的文本隐私链及相应测试；不重构整个聊天 Store。
- `SettingsView.vue` 说明替换交 SET-01；主进程/保护层如需修复只列安全接线请求给 SET-02，不直接改跨域策略。
- SET-09 不直接修改聊天 Store；SET-04 的诊断脱敏、SET-12 的审计脱敏由各自任务负责，本任务做边界事实复核。

## 验收

- [ ] 每条出入站路径都有“已验证保护/未覆盖/尚未验证”的结果和源码或动态证据，不只罗列正向 happy path。
- [ ] UI 说明不再暗示附件、工具、微信、后台任务必然经过桌面文本扫描。
- [ ] 合成测试覆盖 strict/basic、五类控制开关、重复发送/取消以及最终发送内容与界面展示关系。
- [ ] 敏感文件说明有真实执行证据；没有证据时明确限制，不伪造保护开关。
- [ ] 测试与报告不使用真实 PII/用户密钥；历史清理不暗示能撤回已发给模型的数据。
- [ ] 未经 D5 决策不扩大读取阻断、改变微信协议或拦截所有工具结果。

非目标：统一凭据存储、全域敏感文件规则编辑器、网络 DLP、重新设计消息管道。交付单独的覆盖表及残留风险，供 SET-17 和后续隐私项目使用。
