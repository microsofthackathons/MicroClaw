# SET-13 微信连接诊断与受支持渠道策略

阶段：主线 P1；复杂度：M。依赖：SET-01、SET-02、SET-03。D4 未决时不新增渠道或多账号。

## 目标与边界

保持现有微信连接体验，补充可诊断性与插件真实支持的策略。主责 E01–E06；E02/E03 本轮仅显示受限现状，不承诺更多渠道/多账号。

## 实施范围

1. 复用 `ChannelsView.vue`、`WeixinConnectionCard.vue`、channels store 的二维码登录、取消、断开和消息入口。
2. 显示插件/连接状态、最后失败、修复建议及其来源；分清 host 与 MXC containment，不因 host 模式而宣称微信不可用或已受容器保护。
3. 读取 Runtime/微信插件 metadata，核实 DM、群聊、mention、配对、Agent/模型路由是否真实支持；先列能力，再为已批准字段接受控编辑。
4. 字段不受支持或安全语义未明确时保持只读；模型选择调用 SET-08，身份/会话路由不得擅自创建跨用户关联。
5. 其他渠道明确状态和限制；如产品要新增渠道/多账号，另立有独立身份/凭据/安全验收的任务，不隐藏在本任务里。

## 写入范围

- 独占新增：`desktop/src/settings/channels/`、`desktop/renderer/src/components/settings/channels/` 及测试。
- 既有域独占：`views/ChannelsView.vue`、`components/WeixinConnectionCard.vue`、`stores/channels.ts` 及其测试。
- 微信收发/登录/运行时收敛/远程审批核心实现原则只读；必要接点交 SET-02 与安全维护者，不重写协议。
- `PluginsView.vue` 归 SET-15，本任务输出可复用连接入口；路由/底栏接线交 SET-01。

## 验收

- [ ] 已连接、未登录、二维码超时/取消、断开失败、插件缺失、网络断开和保护切换均有明确信息。
- [ ] 当前单账号约束、微信远程审批及消息路由无回归；不把字段缺失当默认可编辑。
- [ ] host 与不同 MXC 强度展示正确；不把关闭保护作为默认排障步骤。
- [ ] 打开/刷新设置不触发插件下载更新、执行修复脚本或改变账号；诊断仅观测。
- [ ] 路由/群聊策略变更经安全路径验证，保留未知字段；不支持的变更不发写 RPC。
- [ ] 假 token/二维码凭据/用户身份不出现在普通日志、错误和截图 fixtures。

非目标：微信协议重写、多微信并发账号、全渠道迁移、任意 Webhook、替换插件安装机制。SET-18 负责未来扩展准入，不因本任务补页面绕开允许列表。
