# SET-18 扩展/技能安装准入与 MCP 受控配置

阶段：条件 P2；复杂度：L。依赖：SET-02、SET-03、SET-06、SET-15、SET-17。产品/安全门控：D2。

## 目标与边界

以“外部代码进入受管 Runtime 的准入闭环”为内聚边界，不让插件/技能依赖/MCP 三种入口各自绕过保护。主责 D03、D07–D09。此任务不实现新的 MCP 引擎或开放任意插件市场。

## D2 必须先确定

- 受支持扩展种类/来源、固定版本与完整性/信任要求，允许的安装/配置/运行模式及能力评审责任人。
- MXC 下哪些能力依旧禁止，是否存在可证明的安全执行后端；“上游能用”不是准入证据。
- 升级/依赖安装/启动命令的审查与撤销语义，何时需要用户确认和重新证明。

未决时可交付准入设计和能力探测；SET-15 的只读清单继续可用。**不能默认建议关闭 MXC，也不能扩大 `plugins.allow`、开放任意 shell 或通用 RPC 来完成任务。**

## 实施范围

1. 在批准的来源/类型子集内实现安装、更新、卸载、启停的计划预览、确认、验证和恢复；保留受管包身份与完整性约束。
2. 技能缺依赖时生成明确的受控安装计划，不直接执行 metadata 中任意命令；实际二进制、下载目标和内容都需要验证。
3. 插件配置只暴露已审查 Schema 字段，凭据使用 SET-17 引用；保持未知字段，禁止把 Schema 当任意写入授权。
4. MCP 仅为已支持运行后端提供配置、凭据引用和诊断；受保护模式未获批准时仍只读/不可执行，不把设置成功当服务可用。
5. 打开清单不执行安装/更新；每次执行有目标身份、锁、取消/失败状态、日志脱敏和可验证恢复。

## 写入范围

- 独占新增：`desktop/src/settings/extension-admission/`、`desktop/renderer/src/components/settings/extension-admission/` 及测试。
- 使用 SET-06/15 的公开读取/刷新契约；旧面板/安装器/lifecycle 的修改在前序任务完成后显式交接。
- 安全策略、完整性/打包资源、执行链路改动由 SET-02 汇总安全审查，不能在领域目录里隐藏旁路。

## 验收

- [ ] 未批准来源、篡改包、路径/命令注入、越界依赖和非广告 Schema 字段被拒绝。
- [ ] 下载中断、更新失败、取消、重启、重复点击和并发变更不留下可执行的半安装状态。
- [ ] 保护模式下禁止的插件/MCP/工具仍不可执行，失败恢复不扩大权限或删除受管 Runtime 文件。
- [ ] 凭据不回显，变更影响可预览，更新/回滚后的包身份和有效状态能验证。
- [ ] 交付逐种类标明“已批准且实测/只读/禁止/未做”；不存在一个开关代表所有扩展安全。

非目标：通用包管理器、任意 npm/shell 安装、重写 MCP 协议、默认启用网关记忆/浏览器、自动追最新版。没有通过准入的种类不得计入可执行交付。
