# Shopping connector 接入调研

调研日期：2026-11-11（Asia/Singapore）。首版范围按讨论聚焦于商品搜索、选购建议和跨平台比价；个人订单、物流、加购及下单只记录后续边界。

本次完成官方公开文档检索、四个开源候选的静态抽查，以及 MicroClaw 连接器架构核对。没有申请平台应用、登录购物账号、安装或执行候选项目，也没有用真实凭据调用商品 API。下文区分已查到的接口、仓库实现和产品建议；公开接口文档不代表 MicroClaw 已获得调用权限。

同日补充：[Agent 比价实现路线调研](agent-price-comparison-patterns-2026-11-11.md)进一步检查了平台商品库、第三方搜索服务、浏览器及手机 App 路线。产品原型可以先验证明确商品链接的浏览器比较，并行推进正式 API 接入；无需等待三家 API 全部获批。

## 建议

Shopping 值得进入下一轮验证，首版定位为“找到可购买的商品、解释差异、提供可核对的价格与来源链接”。先验证淘宝官方商品搜索，再并行确认京东联盟接入；两家数据源通过验证后才承诺跨平台比价。拼多多保留为下一批候选。

这个顺序是基于本次证据完整度的工程建议，不是平台商业价值排名，也不代表淘宝审批一定更容易。实际顺序由可获得的正式权限和样本质量决定。

首版应以官方或明确获准使用的数据源为主。开源 MCP 可以复用工具封装，但不能替代平台的数据权限；本次抽查未找到可直接认定为生产就绪、同时覆盖三家的开源后端。浏览器方案可用于小规模验证，但其登录、页面变化和价格覆盖范围需要单独评估。

## 平台可行性与证据

| 平台 | 已核实的事实 | 对首版的意义 | 仍需确认 |
| --- | --- | --- | --- |
| 淘宝 / 天猫 | 官方存在 `taobao.tbk.dg.material.optional.upgrade`，面向导购物料搜索，支持关键词及多种筛选；请求包含 AppKey、签名和推广位 | 有明确的关键词搜索接入路径，可优先验证 | 开发者及应用资格、场景权限、实际商品覆盖、价格字段、额度及展示要求 |
| 京东 | 官方将京东联盟列为独立开放门户；检索到宙斯商品搜索文档入口，联盟 API 页本次未提取到正文 | 联盟商品数据是候选路线，不能把商家开放平台权限与联盟权限混用 | `jd.union.open.goods.query` 的当前权限、申请条件、详情接口、SKU 与优惠数据范围 |
| 拼多多 | 官方历史材料有 `pdd.ddk.goods.search` 及多多进宝商品库接入说明 | 商品推广数据方向有依据 | 本次读到的接口材料标注为 2020 年更新；现行接口、审批、限额及推广位要求必须重新核实 |

淘宝证据：[物料搜索升级版官方文档](https://developer.alibaba.com/docs/api.htm?apiId=64759)。该页标记“不需用户授权”，但仍要求应用级参数和 `adzone_id`，不能理解为匿名 API。文档还规定，`q` 中含数字商品 ID 的商品链接查询需要“消费者比价场景 ID2”权限；某些单结果标题搜索在未获该权限时不返回推广链接和商品 ID。因此，关键词搜索与商品链接解析应分别验证，不能默认都能开放。

京东证据：[官方开放平台迁移说明](https://jos.jd.com/doc/channel.htm?id=994)、[宙斯商品搜索文档入口](https://jos.jd.com/apilistnewdetail?apiGroupId=49&apiId=15744&apiName=null)、[京东联盟接口入口](https://union.jd.com/openplatform/api/v2?apiName=jd.union.open.goods.query)。搜索索引曾返回宙斯商品搜索说明，但直接打开为 JavaScript 应用；联盟接口页没有可提取正文。因此，本报告不据此保证任一应用可直接调用，也不将宙斯接口当作联盟接口。

拼多多证据：[官方历史商品搜索文档](https://commoncdn.yangkeduo.com/pdd_oms/2021-01-12/2e22638bda0b0f77479f89dab1de2988.pdf)、[官方历史接入材料](https://funimg.pddpic.com/ddjb/2020-12-04/4f8c0c46-e2c3-40e4-bfee-5ac05ba96607.pdf)。历史资料将接口用户授权与开发者应用审核分开描述，不应把“不需用户授权”解释为不需平台准入。

淘宝官方的[技术服务费规则](https://developer.alibaba.com/docs/doc.htm?articleId=104559&docType=1)已经提及 MCP 服务。这只能证明平台存在相应服务分类；本次尚未确认一个满足消费者商品搜索需求的官方 MCP endpoint、工具清单和接入流程。不能据此宣称官方没有 MCP，也不能直接认定存在可用的购物 MCP。

## 首版产品范围

建议从型号明确的数码、小家电等商品开始。示例任务：“预算 1000 元以内选一个显示器，把符合要求的商品列出来，比较同型号的不同报价。”这是产品选择，不是已测出的品类覆盖结论。

首版闭环：需求和预算 → 搜索候选 → 按已授权能力补充详情 → 判断哪些商品可比较 → 展示推荐理由、报价条件和商品链接 → 用户进入平台确认购买。

建议只定义两个数据能力，按实际接入情况开放：

- `shopping.search`：关键词、平台和已支持的筛选条件，返回候选商品、价格信息、来源与抓取时间。
- `shopping.get_product`：按该数据源支持的商品标识补充详情。商品链接解析、SKU 级查询和推广链接生成不因这个工具名称而自动获得支持，应单独检查权限。

跨平台比较是这些结果上的聚合逻辑，不需要假设上游提供一个通用的“最低价接口”。首个数据源上线时应明确显示单平台覆盖。

报价至少区分：

| 信息 | 处理要求 |
| --- | --- |
| 商品与规格 | 平台商品 ID、SKU（若有）、品牌、型号、容量/尺寸、件数、套餐及新旧状态；未识别规格时不直接认定同款 |
| 价格 | 币种、金额、标价/预估券后价/会员价/价格区间；未知价格为缺失值，不能填 0 |
| 条件 | 优惠门槛、会员/新客资格、地区、运费、补贴、拼团条件；上游未返回时明确未知，不推断可享受 |
| 来源 | 平台、店铺、数据来源类型、原始链接、查询时间，以及覆盖范围 |
| 比较结果 | 规格匹配依据与不确定项；只在可比条件下排序；推荐理由与推广佣金分离 |

产品文案使用“本次查询、相同规格与适用条件下的较低报价”，避免把有限商品库结果称为全网最低价。加入推广链接时应展示其性质，不能让佣金替代用户的预算和选购条件。

## 与现有 connector 架构的关系

本次架构核对基于独立的连接器开发分支，其中的统一连接管理、连接器类型和工具运行时可继续承担目录、状态及工具接入。这些实现不随本研究记录合入 upstream；下述内容是集成建议，不表示公开主分支已经具备该连接器体系。关键是先决定谁拥有数据源凭据。

商品搜索可能使用产品运营方的联盟应用，而不需要每位用户授权自己的淘宝/京东/拼多多购物账号。因此 UI 应区别“购物数据源可用”与“个人购物账号已连接”，不应为了套用 Gmail 的连接流程制造一个账号授权状态。

建议的职责划分：

| 部分 | 职责 |
| --- | --- |
| MicroClaw | 需求收集、商品结果展示、比较逻辑、来源与价格条件、可用状态 |
| 平台适配后端 | 调用已授权 API、保存应用凭据、限流、字段归一化、按许可规则缓存 |
| OpenClaw | 工具注册、发现、调用及现有权限策略 |

如果使用产品共享的 AppSecret，应由服务端保管；桌面端的系统加密存储不能把随产品分发的共享秘密变成不可提取的秘密。若采用用户自备开发者凭据模式，则属于另一种配置体验，不能混作普通消费者购物账号登录。

在确定数据源之前不建议扩展连接器通用协议。先验证现有状态表示是否足够，再最小化表达服务可用性。若最终采用第三方 MCP，保留其原生工具身份和 OpenClaw 权限控制；不要为了统一工具名称再包一层调用来绕过宿主策略。

## 下一步可执行验证

1. **淘宝：** 用运营方开发者账号确认应用及推广位，核对搜索接口权限；单独核对商品链接查询/消费者比价场景权限。取得一份真实搜索响应后，再决定详情和比价字段。
2. **京东：** 在联盟业务入口核实应用资格、搜索及详情能力；取得真实 SKU、价格、店铺和优惠条件样本。与淘宝验证并行，谁先具备正式可用数据，谁先完成单平台闭环。
3. **样本验收：** 建议准备 20 个固定关键词及至少 10 组已知同款/不同规格商品，记录搜索成功率、字段缺失、链接有效性、响应耗时及人工可核对的价格条件；明确区分数据错误、价格时效和用户资格差异。这是验收建议，本次未执行。
4. **两平台比较：** 验证同款匹配及报价条件后开放跨平台结果；一个平台失败时返回部分结果及覆盖状态，不捏造缺失价格。
5. **拼多多：** 获取当前正式文档和权限后复用结果模型，重点确认价格、SKU、拼团与优惠条件能否表达；在此之前不列为已支持。

正式接入前仍待核实：平台当前准入与场景许可、数据展示/缓存要求、调用额度和成本。现有公开资料不足以替代开发者后台和真实样本验证，因此本报告不承诺上线日期或零接口成本。

## 后续个人订单与交易

商品搜索数据、联盟推广订单、商家店铺订单和消费者自己的全部订单是不同能力。本次没有证据证明上述候选提供通用的个人买家 OAuth 与完整订单读取，因此不能从搜索接入推导出订单查询已可实现。

后续扩展个人订单需要独立确认买家身份、授权和数据范围；加购、下单还涉及商品规格、收货信息和最终金额的交互。这些应作为下一轮调研，不纳入当前搜索与比价首版的完成条件。
