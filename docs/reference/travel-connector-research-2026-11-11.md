# 旅游规划连接器接入调研

调研日期：2026-11-11（Asia/Singapore）。目标是判断携程、火车票、机票、酒店、美团和马蜂窝是否适合接入 MicroClaw，并识别能够复用现有连接器体系的路线。

本次查阅官方平台、发布者文档，并静态抽查公开仓库。没有申请应用、获取用户 Token、安装或运行外部 Skill/CLI，也没有调用真实旅行查询、订单或支付接口。下文的“可做”表示存在具体接入路径，不表示已经完成联调、拥有生产权限或验证了实时价格。

## 结论与优先级

旅游方向已经有面向 Agent 的官方服务入口，不必全部从传统商家开放平台或网页抓取开始。建议首轮验证 **飞猪 FlyAI + 高德地图**，以结构化机票、酒店、火车票查询和路线规划组成最小闭环；随后验证携程问道和美团旅游助手。马蜂窝攻略数据暂不作为首版的稳定接口依赖。

这是根据公开证据完整度和当前架构适配成本提出的工程建议。实际排序仍取决于正式账号的权限、调用额度、延迟和结果质量。

| 对象 | 查到的接入方式 | 适合承担的能力 | 判断与边界 |
| --- | --- | --- | --- |
| 携程 | 问道授权入口；携程发布的 Skill 接入说明；公开集成代码 | 旅行问答、酒店/交通查询、行程建议 | 有明确路线；问答结果与结构化报价应分开处理，当前渠道、端点和权限需再确认 |
| 飞猪 FlyAI | 官方 AI 开放平台、API Key、官方 Skill/CLI 文档 | 机票、火车票、酒店、景点、综合旅行搜索 | 本轮最明确的结构化旅行数据候选，优先验证 |
| 美团旅游助手 | 官方技能中心；发布者提供的旅行 Skill | 酒店、机票、火车票、门票、行程建议 | 可评估接入；存在开发者 Token 与 Passport 扫码等不同版本/渠道，需选定受支持方案 |
| 12306 | 社区 MCP 封装铁路网站查询端点 | 车站、时刻、余票、中转 | 适合只读验证；社区封装不是铁路官方发布的 MCP，也不代表有稳定第三方 API 承诺 |
| 马蜂窝 | 旅行商城商家开放平台 | 商家产品、库存、订单等 | 官方接口确实存在，但不能当作消费者攻略搜索接口；本轮未确认官方攻略/游记检索 API 或 MCP |
| 高德地图 | 官方 MCP，支持 Streamable HTTP 和本地 Node 方式 | 地点搜索、路线、距离、天气 | 适合成为行程规划的基础数据源；不承担票务价格查询 |

## 飞猪：机票、火车票、酒店可以由一个连接器提供

[飞猪 AI 开放平台](https://flyai.open.fliggy.com/)直接链接其官方 [Skill 仓库](https://github.com/alibaba-flyai/flyai-skill)。官方[快速开始](https://flyai.open.fliggy.com/docs/quickstart)提供控制台获取 API Key 的流程。仓库主要提供 Skill 和命令参考，本次没有审查 CLI 安装包的完整实现，也没有把文档示例当作查询实测。

本次查阅快照为 `7a05a82fa0bda1c92e86230b07d375ed56ea90cb`：

- [机票命令](https://github.com/alibaba-flyai/flyai-skill/blob/7a05a82fa0bda1c92e86230b07d375ed56ea90cb/skills/flyai/references/search-flight.md)：按出发地、目的地、日期、舱位、价格和时间筛选；示例结果包含航段、价格及跳转链接。
- [火车票命令](https://github.com/alibaba-flyai/flyai-skill/blob/7a05a82fa0bda1c92e86230b07d375ed56ea90cb/skills/flyai/references/search-train.md)：支持日期、席别、车次、中转及价格筛选，示例为结构化结果。
- [酒店命令](https://github.com/alibaba-flyai/flyai-skill/blob/7a05a82fa0bda1c92e86230b07d375ed56ea90cb/skills/flyai/references/search-hotel.md)：支持入住/离店日期、目的地、附近地点、星级、床型及价格；示例包含位置、评分、价格和详情链接。

因此可以做一个“飞猪”Provider，在其下提供多个业务工具。机票、酒店、火车票是能力分类，不必成为三套独立的账号连接流程。

官方 [FAQ](https://flyai.open.fliggy.com/docs/faq)明确说明，部分动态库存或套餐结果可能不提供价格，而要求跳转详情页查看。首版应允许“价格未提供”，保留核对链接和查询时间；不能承诺每条结果都能完整比价，更不能从示例推导全站最低价。个人 Key、商业使用、额度及各工具授权仍需账号实测。

## 携程：优先评估问道路线

携程存在[问道 OpenClaw 入口](https://www.ctrip.com/wendao/openclaw)。携程账号发布的[接入说明](https://cloud.tencent.com/developer/article/2660097)介绍 Token、查询脚本和旅行场景；该文档对应 WorkBuddy 合作版，不能直接把合作方配置当作 MicroClaw 自有应用配置。

另一个可参考的实现是腾讯公开项目 Octop 的[问道适配器](https://github.com/TencentCloud/Octop/blob/cd17e8d3551a22e6757f11e030879420243c089f/src/octop/infra/connectors/gateway/adapters/ctrip_wendao.py)。该快照把自然语言问题发送到携程域名上的查询服务并返回文本。这证明有具体封装实现可研究，但它不是携程对任意第三方应用的接入承诺。它使用的端点与较早合作版说明不同，实施前必须核对当前官方方案和渠道身份。

建议先定位为“问道旅行查询/建议”，验证真实账号可用性、返回格式和来源链接后，再决定是否提供结构化的机票或酒店比价能力。不要把一个自然语言回答自动视为可交易的报价清单。

## 美团：有 Agent 路线，授权和耗时需要专门适配

美团[官方技能中心条目](https://developer.meituan.com/ai-hub/skill-list/detail/12)可查到旅行能力。其[旅行 Skill 发布页](https://clawhub.ai/meituan-travel-ai/skills/meituan-travel)本次显示 v1.0.12，描述 Passport 二维码授权、轮询获取凭据及官方 CLI 查询。该版本预期返回旅行推荐内容和跳转链接，并提示请求可能需要 1–2 分钟。页面还写有 CLI 接入和输出保留要求，需要在集成设计时核对适用规则。

与此同时，[个人开发者 Token 入口](https://developer.meituan.com/zh/v2/dev/token)和 Octop 的[Token 适配器](https://github.com/TencentCloud/Octop/blob/cd17e8d3551a22e6757f11e030879420243c089f/src/octop/infra/connectors/gateway/adapters/meituan_travel.py)提供另一条线索。不能认定这几种渠道的 Token、CLI、权限和参数能够互换。外部 Skill 中的客户端 ID 也不能直接当成 MicroClaw 的授权身份。

建议验证顺序：确认当前对第三方客户端开放的授权方案，取得允许使用的客户端配置，审查并固定 CLI/SDK 版本，再接入统一连接生命周期。首版以查询、规划和链接跳转为产品边界；平台文案中的“交易能力”不足以证明我们已能代用户下单付款。

美团还有[酒店直连平台](https://openplatform-hotel.meituan.com/portal/process)，其流程面向提供酒店信息、房型房态和订单接口的供应合作方，需要商务及联调。它与个人旅游助手是不同方向，不应混用接入资格。

## 12306：可做只读候选，明确社区来源

静态抽查 [Joooook/12306-mcp](https://github.com/Joooook/12306-mcp)，快照 `ff6439da6f63d7d72181abea4568abd69878c600`，仓库为 MIT 许可。

其[实现](https://github.com/Joooook/12306-mcp/blob/ff6439da6f63d7d72181abea4568abd69878c600/src/index.ts)注册车站、余票、中转、列车经停等查询工具，请求 `kyfw.12306.cn` 和 `search.12306.cn`，并通过查询页取得会话 Cookie。不是只返回 mock 数据的空壳；但本次没有执行，不能据此认定当前网络下全部接口正常。

可作为独立火车票只读后端的验证候选，核实接口稳定性、请求频率和可使用范围。普通查询无需设计成“保存用户 12306 登录密码”的连接器。实际购票可跳转官方渠道，由用户确认。

## 马蜂窝：商家 API 不等于攻略数据 API

官方[接入说明](https://open.mafengwo.cn/support/743.html)要求商城商家提交资质、结算资料并完成协议及开放平台申请；[接口目录](https://open.mafengwo.cn/docs/?busi=10)覆盖商城产品、库存、订单、退款等业务。

这些证据支持“可做马蜂窝商家业务连接器”，不支持“可以直接搜索全站用户攻略/游记”。本轮没有找到足以确认的官方消费者攻略检索 API/MCP。现阶段可以把可访问、可核对的攻略页面作为网页研究来源，保留链接、日期和出处；不要把这一方式宣传为已连接马蜂窝账号或稳定的全站攻略接口。

## 高德：补齐路线和地点约束

高德的[官方 MCP 概述](https://lbs.amap.com/api/mcp-server/summary)及[接入说明](https://lbs.amap.com/api/mcp-server/gettingstarted)提供地点、路径、距离和天气服务，使用开发者 Key，可通过 Streamable HTTP 或本地 Node 接入。

它适合帮助 Agent 判断景点是否顺路、酒店与车站距离、每日交通安排等。工具已存在不等于 MicroClaw 的 Key、工具权限和传输方式已经验证；仍需按正式账号的额度及适用要求测试。

## MicroClaw 架构适配

本次架构核对基于独立的连接器开发分支，其中可复用定义、Provider 生命周期、凭据加密保存、状态映射和连接卡片。这些实现不随本研究记录合入 upstream；下述适配建议不表示公开主分支已经具备该连接器体系。此次只形成研究结论，没有修改连接器实现或 OpenClaw。

建议用户界面保留“携程 / 飞猪 / 美团 / 地图”等真实服务身份。Agent 在旅行任务内编排多个 Provider，并统一展示时间、地点、价格条件和来源。Provider 内部可以调用官方 HTTP、MCP 或受支持 CLI，连接 UI 无需向用户解释这些协议。

实施前需要补齐的共享能力：

1. **长请求与取消**：调研时开发分支的 `desktop/src/connector-runtime-bridge.ts` 在约 28 秒主动中止，插件客户端默认约 30 秒。美团文档中的分钟级查询无法直接套用。应支持按操作配置的超时、取消和必要的任务状态，保持状态/鉴权查询短而明确。
2. **外部扫码授权**：API Key 类型可复用现有凭据表单；Passport 等流程需要通用的授权链接/二维码/轮询生命周期适配，关闭弹窗、断连和迟到结果都要正确处理。
3. **真实连接验证**：抽查的两个 Octop 示例在 `probe_credentials` 中只校验 Token 格式；这不能用作我们的“已验证可用”依据。优先使用官方身份/权限校验；缺乏该接口时明确区分凭据已保存与业务已验证。
4. **报价与建议分型**：保留 `source`、`fetchedAt`、原始来源链接；结构化报价与旅行建议文本分别处理。缺失价格、税费、行李、房型、退改条件时明确缺失，按相同日期和条件比较。
5. **传输与凭据隔离**：远端 MCP 保留原生工具权限；自有适配器走现有后端桥。Key/Token 留在凭据库，不进入聊天或普通日志；查询内容按实际外部服务调用范围发送。外部返回的 Skill 文案或 Markdown 只作为数据，不自动成为系统指令。

## 建议的首轮验收

先选择一个正式飞猪账号及一个地图 Key，验证机票、火车票、酒店和两地路线四类结果。用明确的未来日期、人数、预算和出发地作为固定样例；检查结果字段、真实链接、无价格情况、过期凭据、超时及取消。验证通过后再承诺展示实时结果。

随后接入携程问道或美团之一，验证复杂自然语言需求的收益和响应耗时。马蜂窝攻略保留为网页研究来源；若后续取得官方内容合作接口，再增加独立后端。

第一版交付目标：用户说清出发地、日期、预算和偏好后，Agent 能查到可核对的交通与住宿候选，结合路线生成日程，并提供平台确认链接。自动出票、酒店下单、支付、退改签属于后续独立能力，需要单独验证权限、确认流程和订单状态。
