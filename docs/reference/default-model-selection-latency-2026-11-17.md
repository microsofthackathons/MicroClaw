# 默认模型切换耗时优化

## 改动范围

设置页默认模型切换在 OpenClaw 2026.10.10、`config.set` 可用且启用热更新时，采用轻量写入，再确认目标默认模型、配置哈希和运行时已应用版本。其他版本、缺少方法或超出已验证变更范围时继续使用 `config.patch`。

轻量写入只改全局 `agents.defaults.model.primary`，可同时追加一个已通过提供商目录验证的模型，以及本地模型所需的单个允许项。保留已有模型定义、fallback、别名、智能体专用选择、模型策略、凭据和其他配置。完整写入基于本地未脱敏源配置，不使用 Gateway 返回的脱敏视图。数组必须保留原内容再追加目标模型，否则回退到原来的补丁语义。

千问、MiniMax 的目录验证，以及 Copilot 的认证和已准备目录检查继续执行。本地模型保留组件准备、模型配置和文件检查。仍按配置版本防止并发覆盖；响应丢失不会重发写入。本地切换保留中断后通过读取状态恢复的能力。

## 隔离对照（2026-11-17，UTC+8）

使用真实 OpenClaw 2026.10.10 Gateway、临时状态目录、随机本地令牌和模拟提供商端点。在同一 Gateway 中交替调用旧 `config.patch` 路径和新路径，每种提供商切换 6 次，排除前两次预热后，每条路径保留 2 个样本。统计包含配置写入及运行时确认，不只比较 RPC 返回速度。

| 提供商 | 原路径样本 | 新路径样本 | 原路径中位数 | 新路径中位数 |
| --- | --- | --- | ---: | ---: |
| 千问 | 6.757、5.308 秒 | 3.639、1.767 秒 | 6.033 秒 | 2.703 秒 |
| MiniMax | 7.822、5.891 秒 | 3.003、2.879 秒 | 6.857 秒 | 2.941 秒 |
| 本地模型配置写入 | 6.673、4.899 秒 | 3.332、1.758 秒 | 5.786 秒 | 2.545 秒 |

原始数据：`build/reports/default-model-selection/comparison.json`。

测试确认：默认值与目标一致，fallback、智能体专用模型和模型策略保留，凭据未改变，Gateway 连接代际和进程保持不变，没有推理请求。千问和 MiniMax 的首次切换还覆盖了模型目录登记；本地行使用外部 loopback 模型配置，仅测经过检查后的共享写入路径，不加载 GGUF 或启动 llama.cpp 服务。对应检查另由本地模型单元测试覆盖。

这些是少量隔离样本，不能保证生产时延。真实用户的目录网络请求、Copilot 认证检查、MXC 复核、模型准备及界面刷新不包含在这些数字里。API `config.set` 本身较早返回，客户端仍等待目标运行时版本生效后才报告切换成功。

## 验证与复测

- 196 项默认模型写入、切换、本地模型服务和配置检查测试通过。
- 真实 Gateway 对照场景完成全部 18 次切换。
- TypeScript 与变更文件 ESLint 检查通过。

复测 `desktop/src/default-model-selection.integration.test.ts` 时显式设置：

- `MICROCLAW_OPENCLAW_TEST_PACKAGE_DIR`：待验证的 OpenClaw 包目录。
- `MICROCLAW_GATEWAY_E2E_PARENT`：已创建的临时测试父目录。
- `MICROCLAW_DEFAULT_MODEL_REPORT`：可选 JSON 报告输出路径。

测试不读取用户的 API Key，不操作用户的默认模型；子进程状态、配置、设备身份和工作区均隔离。更新源码后需要重新构建桌面主进程；已安装 EXE 需要重新构建安装包后生效。
