# 内置 OpenClaw 的统一安装与升级

> 当前验收范围（2026-11-12）：优先验证新用户从 ASAR 安装与首次打开。跨版本升级、Doctor 迁移与恢复设计暂缓；下文的升级部分是待验证实现说明，不能视为 10.5 → 10.10 已验证成功。

## 运行时来源

Web 安装器使用桌面 ZIP 内的 `resources/openclaw.asar` 和 `resources/node.exe` 安装核心，不再在用户机器上先执行一次全局 `npm install -g openclaw`。构建阶段仍使用 npm 准备、审核并打包固定版本的核心和依赖。

Git、Node/npm 环境准备和可选组件仍有各自步骤；此变更不宣称整套安装完全离线。独立的依赖安装脚本及旧 npm 升级恢复代码保留，但不再属于 Web 安装器的核心安装路径。

| 内容 | 位置 |
| --- | --- |
| 桌面程序和随包 Node/ASAR | `%USERPROFILE%\.microclaw` |
| 唯一的 MicroClaw 核心运行目录 | `%APPDATA%\microclaw\runtime\openclaw` |
| OpenClaw 配置、数据库和账号数据 | `%USERPROFILE%\.openclaw` |
| 桌面设置和连接器凭据 | `%APPDATA%\microclaw` |
| 升级事务日志 | `%USERPROFILE%\.microclaw\upgrade\bundled-upgrade.json` |
| 白名单数据恢复归档 | `%USERPROFILE%\.microclaw\backups\bundled\<id>\state.tar.gz` |

`microclaw-openclaw.cmd` 使用这同一份内置 Node 和运行时。安装器不覆盖其他工具安装的全局 `openclaw` 命令。旧独立 CLI 可能无法读取升级后的数据库，操作 MicroClaw 数据时应使用 `microclaw-openclaw`。

## 安装顺序

1. 停止当前应用，检查 Gateway、OpenClaw/npm 活跃进程和未完成事务；先恢复旧事务，拒绝无恢复来源的未知状态或降级。
2. 获取与旧安装事务相同的独占锁。对已有数据，通过已审核的旧版本快照接口生成 SQLite 一致性快照和白名单计划，形成 SHA-256 验证的恢复归档。新用户无数据库时只保存已有的少量桌面设置及管理文件。
3. 校验桌面 ZIP 与安装清单的摘要，在临时目录展开。逐项保留旧桌面资源，发布新程序；不会清空配置、备份和事务目录。
4. 调用新版桌面的 `--prepare-installer-runtime`，将 ASAR 展开到暂存目录，保留旧运行目录为 `openclaw.previous` 后发布新目录。发布失败尝试恢复旧目录。
5. 校验运行时回执、路径、入口和目标版本；托管微信/本地模型插件的 OpenClaw peer 绑定到这同一目录。旧 peer 保留供失败时恢复，外部 npm 安装本身不被删除。
6. 写配置、复制管理资源、发布精简卸载器、创建入口。无法读取的现有配置会报错并保留，不再静默替换成空配置。
7. 使用内置运行时执行配置校验。跨核心版本时，在已验证恢复点之后运行目标版本 `doctor --fix --non-interactive`，随后做受控的 Gateway 就绪和各 Agent 历史读取校验。新用户和同版本修复不运行跨版本 Doctor。
8. 校验完成后提交事务，再清理旧程序目录。数据恢复归档保留。安装完成页仍由用户选择关闭或打开应用。

真实 10.5 数据验证发现，schema 25 不能仅依靠启动 10.10 自动完成升级，目标核心会明确要求 Doctor。因此该步骤属于跨版本必要迁移，不能为了减少等待直接跳过。

## 暂时启动的迁移校验 Gateway

跨版本校验使用独立本地端口、临时校验配置、Windows Job 进程生命周期和 overlapped stdin lifeline。渠道、定时任务、hooks 和 heartbeat 在该校验配置中关闭，服务修复策略设为 `external`。这不是启动桌面窗口，也不会启动第二个正常用户会话。

`/readyz` 成功不代表 Agent 数据已完成准入；安装器还通过官方 CLI 读取已配置 Agent 的历史。只对明确的“startup inspection/preparation 尚未完成”错误做有期限等待，其他错误直接失败。校验进程必须正常退出后才能提交；超时或失败会回收其进程树再进入恢复。

## 缓存和替换

缓存标识含桌面版本、OpenClaw 版本及 ASAR 文件表的 SHA-256。文件表包含归档文件的完整性字段，所以同版本重新打包但依赖树不同，也会失效重建；这不等于每次启动都逐文件校验已展开目录。

普通桌面启动不允许直接跨 OpenClaw 版本替换现有运行时。跨版本准备必须处于安装器持有的、已创建数据恢复点的事务中。未完成或无法解析的升级日志会阻止普通启动，并提示重新运行安装器恢复，避免打开半成品。

程序目录通过改名保留到提交时，而不是打进数据备份再复制一份。短期保留旧程序和新程序会占用额外磁盘空间；白名单归档仍排除模型缓存、浏览器配置、安装包 ZIP、运行时和插件依赖代码。

## 回滚与中断恢复

- 发生安装/配置/迁移/验证失败时，先确认相关进程停止，再验证数据归档；数据和程序恢复作为同一事务处理。
- 恢复已捕获的 SQLite 文件时，处理旧 WAL/SHM/journal，避免它们重放到恢复的数据库上。
- 升级后产生或修改的白名单内容先留在 `failed-state`，并记录原路径索引；不以直接丢弃这些文件作为恢复方式。
- 旧桌面、运行时、托管插件 peer、管理资源及卸载器恢复到原位置。恢复完成后才将日志标记为 `rolled-back` 并放行应用。
- 中途退出后，再次运行安装器会读取写入前已落盘的操作记录并恢复；备份损坏、路径重定向或活跃状态所有者会阻止自动恢复，保留证据。
- 校验提交后清理旧程序失败只留下可清理的旧文件，不把已成功提交的安装误报为数据回滚。

历史 npm 升级尚未完成时，不自动跨事务格式接管；先用原安装器完成其恢复。白名单快照接口目前审核了 OpenClaw 2026.10.5 和 2026.10.10，其他源版本需要增加明确的迁移/快照契约后支持。

## 验证范围

单元与集成测试覆盖全新安装不调用 npm 核心安装、快照缺失/损坏、发布中断、缓存保留、SQLite 和 WAL 恢复、配置拒绝重置、CLI 绑定、插件 peer 和卸载器恢复、普通启动拦截及归档身份变化。

本机真实跨版本验证材料位于 `build/bundled-upgrade-validation-20261112/`。测试使用独立状态、测试历史和测试凭据，程序/核心来自真实桌面产物；系统注册表、Defender、OfficeCLI 下载等宿主安装步骤不在该隔离验证范围内。具体通过结果须以该目录最终结果文件及测试日志为准。
