# MicroClaw 安装耗时分析（2026-10-15）

## 结论与口径

- 用户提供的这次安装实际执行约 **5 分 44 秒**，20 个步骤的计时合计 **344.15 秒**；最终服务启动失败，不能把它算作一次成功安装。
- 最大耗时是“配置与数据迁移” **216.52 秒（62.91%）**，其次是“启动服务” **81.66 秒（23.73%）**；两者合计 **298.18 秒（86.64%）**。
- 这是已有 OpenClaw、Git、Node.js、桌面客户端及插件的覆盖安装，不是全新机器的首次安装。下载依赖和首次完整安装的耗时不能用该日志推算。
- 当前源码的隔离验证与旧安装包的历史日志分别统计，不把不同条件的数字拼成“新版完整安装耗时”，也不把嵌套计时重复相加。
- **首次分析时，常规回归通过，但扩展 trace 发现内部开机标识查询仍被路由至 AppContainer。后续执行边界修正及隔离复测见第五节；尚不能据此宣称完整安装和桌面交接均已修复。**

### 为什么“迁移”需要这么久

安装器当前调用的是官方 `openclaw doctor --fix`，并不是仅执行一次 SQLite 表结构升级。该步骤包含官方 Doctor 的检查和修复流程。

历史安装器成功分支没有保留该次 Doctor 的详细输出，只有 216.52 秒总计时，所以不能进一步断言其中多少秒属于数据库升级、插件检查、模块加载或其他检查。

## 二、当前源码的隔离验证

### 条件

- 测量日期：2026-10-15，UTC+8；Doctor 测量于 17:25:59 开始，正式运行时集成测试于 17:31:39 开始。
- Windows、本机 Node.js **v24.18.0**、已安装的官方 OpenClaw **2026.10.3**；使用当前源码中的兼容预加载与沙箱逻辑，没有修改已安装的官方包。
- 使用新建的独立 HOME、状态、临时目录和随机本地端口，不读取真实 API Key；模型、渠道及插件未做用户侧配置。
- Doctor 使用 `doctor --fix --non-interactive`，并将 service repair / supervisor 设为 `external`，避免操作真实系统服务；因此不是对真实安装步骤的原样重放。

- 每个场景只有一次测量，重复场景复用该夹具的状态与 V8 缓存；不是统计意义上的稳定性能基准。

### 扩展验证发现的残留问题

额外测量开启完整官方 startup trace，并保留整个启动输出。在该场景中，Gateway 虽然于 73.557 秒到达健康端点，但仍有 **2 次**固定的内部开机标识查询出现：

同一次启动也有符合识别条件的查询正确走 `BYPASS (internal boot identity)`。这说明独立查询测试通过不等于启动期间每种调用上下文都覆盖了；**尚不能认定内部查询被沙箱误接管的问题已经完全修复**。具体的 worker 入口 / 调用栈差异仍需进一步确认，不应为了让测试通过而放开任意 PowerShell 执行。

常规集成测试只保留末尾 20,000 字符日志，本次不能用它的无匹配断言证明完整启动过程中从未出现接管。后续应保留完整输出，或独立累积相关事件标记，避免日志截断漏掉早期事件。

额外测量最初还出现过未达到健康端点的样本：自建夹具设置了授权范围之外的 XDG 目录等不同环境。恢复为与正式夹具一致的目录环境后才达到健康端点。这些失败或不同条件的数字不用于计算提速，也不能混同为真实用户的一次安装结果。

## 四、后续优化优先级

1. 正确性优先：补齐完整日志事件断言，定位扩展场景仍被误接管的内部查询，再单独复测真实桌面交接及窗口退出。不能以健康端点返回成功代替完整安装成功。
2. 性能优先：继续拆分 Doctor 内部检查，再判断可否在官方兼容边界内减少重复、非关键工作；不能直接跳过必要数据库迁移或活进程所有权检查。
3. 复测当前源码中“ACL 未变化则不写入”的优化，尤其是大型依赖目录的重复启动；首次确有权限变化时仍必须写入。
4. 完成上述检查后重新打包，在明确隔离的测试账户或虚拟机做完整安装，才能给出新版端到端耗时及稳定提速结论。

## 五、宿主运行时与工具执行边界修正

2026-10-15 18:27 起的后续验证针对启动命令被工具沙箱误接管的问题。最终加强断言的套件于 18:31:24 开始，13 项全部通过；下表采用最终轮次的数字。

- 移除 `sandbox-cp-hooks.js` 中依据调用栈识别开机查询的全局豁免。该方案会漏掉打包到其他 worker 内的同一段内部代码。
- 新增 `sandbox-host-runtime.js`：只为版本、真实路径及已加载源码 SHA-256 全部匹配的十个官方控制面模块提供受限适配器。适配器只提供固定的系统开机身份查询和合法整数 PID 的进程创建时间查询，不提供任意宿主 shell 执行接口。
- 进程创建时间优先使用 Windows 原生只读 API；不可用时才运行固定的系统 PowerShell 查询。调用方不能改写脚本、工作目录、环境或超时。
- 普通工具、插件的 `child_process` 导入不获得该适配器；即使命令文本与内部查询完全相同，仍进入 AppContainer。受信模块执行其他命令也继续经过原有工具沙箱。
- MicroClaw 管理的 Gateway 设置 `OPENCLAW_NO_AUTO_UPDATE=1`，避免 OpenClaw 的独立自更新流程探测全局 npm/pnpm 安装归属或修改安装器管理的运行时。MicroClaw 自己的更新入口保留，裸 CLI 不受此子进程环境设置影响。
- 所有工具保护仍从进程启动立即生效，没有“先关沙箱、启动后再打开”的空窗；数据库目录范围和敏感路径保护保持不变。
